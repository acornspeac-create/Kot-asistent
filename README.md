# KOT Assistant

Личный Android‑ассистент в стиле «Jarvis»: голосовой ввод, озвучка ответов, локальная память диалога и подключение к ИИ через собственный сервер.

## Что уже есть

- Android‑приложение на Kotlin + Jetpack Compose.
- Голосовой ввод через системное распознавание речи Android.
- Озвучка ответов через Android TextToSpeech.
- Локальная память последних сообщений на телефоне.
- Поле для адреса собственного backend‑сервера.
- Серверный шлюз на Node.js к OpenAI Responses API.
- API‑ключ хранится только на сервере, а не в APK.
- GitHub Actions автоматически собирает debug APK.
- KOT Flasher Agent для локальной работы с Android через ADB/Fastboot.

## Структура

- `app/` — Android‑приложение.
- `server/` — минимальный backend‑сервер.
- `flasher/` — локальный агент для определения и прошивки Fastboot‑устройств.
- `.github/workflows/android.yml` — автоматическая сборка APK.
- `SECURITY.md` — правила хранения секретов.

## Запуск backend

Нужен Node.js 20 или новее.

```bash
cd server
export OPENAI_API_KEY="ваш_ключ"
export OPENAI_MODEL="gpt-5.6-luna"
npm start
```

Проверка:

```bash
curl http://localhost:8787/health
```

На реальном телефоне укажите в приложении HTTPS‑адрес опубликованного сервера. Для локальной разработки можно использовать адрес компьютера в вашей Wi‑Fi сети.

## KOT Flasher Agent

Саму прошивку нельзя выполнять на Railway: облачный сервер не видит USB‑порт компьютера. Поэтому KOT использует локальный агент из папки `flasher/`.

Текущая версия умеет:

- находить Android‑устройства через ADB и Fastboot;
- читать модель, product/device, Android, fingerprint и батарею;
- проверять состояние Fastboot и bootloader;
- проверять SHA‑256 образов и соответствие product;
- показывать dry‑run план без записи;
- автоматически прошивать перечисленные разделы на совместимом Fastboot‑устройстве;
- при необходимости выполнять wipe и reboot после прошивки.

Перед использованием установите Android Platform Tools и Node.js 20+:

```bash
cd flasher
npm run devices
node kot-flasher.mjs inspect SERIAL
node kot-flasher.mjs plan SERIAL ./firmware.example.json
```

Реальная запись начинается только после явного `--execute`:

```bash
node kot-flasher.mjs flash SERIAL ./firmware.example.json --execute
```

KOT Flasher не обходит FRP, OEM/account lock и не выполняет скрытую разблокировку bootloader. Производительские протоколы вроде Samsung/Odin будут подключаться отдельными драйверами.

Подробности: `flasher/README.md`.

## Сборка Android APK

GitHub Actions собирает APK автоматически после изменений в ветке `main`.

Также проект можно открыть в Android Studio и собрать обычным способом.

## Безопасность

Никогда не вставляйте OpenAI API key прямо в Android‑код, APK, README или публичный репозиторий. Ключ должен находиться только на backend‑сервере.

Для KOT Flasher используйте отдельный длинный `KOT_FLASHER_TOKEN`. Агент по умолчанию слушает только `127.0.0.1`.

## Максимальный доступ

В Android-приложении есть единый экран **«Максимальный доступ»**, чтобы не получать одинаковые запросы при каждом действии.

В одном месте можно выдать основные runtime-разрешения, доступ ко всем файлам, overlay, уведомления, Accessibility и Device Admin.

Если KOT установлен как **Device Owner**, приложение сначала пытается автоматически выдать доступные runtime-разрешения через DevicePolicyManager и только оставшиеся показывает как системный запрос.

Для тестового/выделенного телефона Device Owner обычно назначают после сброса устройства и установки APK:

```bash
adb shell dpm set-device-owner tj.kot.assistant/tj.kod.assistant.KotDeviceAdminReceiver
```

Android может отказать в назначении Device Owner, если устройство уже полностью настроено или на нём есть несовместимые аккаунты/профили.

Некоторые специальные права — Accessibility, Notification Listener, overlay и all-files access — Android включает через отдельные системные экраны. После однократного включения KOT не должен повторно запрашивать их при каждом действии.

## Автоматическая прошивка по производителю

KOT Flasher v0.2 автоматически выбирает драйвер и режим:

- Samsung → Download Mode + Heimdall;
- Xiaomi / Redmi / POCO → Fastboot;
- Google Pixel → Fastboot;
- OnePlus → Fastboot;
- Motorola → Fastboot;
- OPPO / realme / vivo / iQOO / Nothing / Sony и совместимые модели → Fastboot;
- неизвестные совместимые модели → generic Fastboot.

Перед записью KOT проверяет manifest и соответствие устройства.

## Локальные команды режима владельца

Эти команды выполняются на телефоне до обращения к AI-серверу:

- `домой` / `на главный экран`;
- `назад`;
- `недавние` / `последние приложения`;
- `быстрые настройки`;
- `уведомления`;
- `открой настройки`;
- `открой Wi-Fi`;
- `открой Bluetooth`;
- `открой <название приложения>`;
- `заблокируй экран`;
- `режим владельца` — показать состояние Device Owner / Accessibility / разрешений;
- `найди файл <имя>` — локальный поиск при выданном all-files access;
- `установи apk <полный путь>` — подготовить APK и открыть установку.

Device Owner включает политику AUTO_GRANT для будущих runtime-разрешений. Специальные доступы Android (Accessibility, overlay, notification listener, all-files и источник установки APK) включаются один раз через системные экраны.


## Реальный офлайн ИИ

KOT поддерживает локальный текстовый ИИ через **Google LiteRT-LM**.

- runtime: `com.google.ai.edge.litertlm:litertlm-android:0.17.1`;
- рекомендуемая модель: `Qwen3 0.6B INT4 no-think` в формате `.litertlm`;
- модель скачивается из раздела **Офлайн-модели** одной кнопкой;
- KOT сначала пробует GPU/OpenCL, затем автоматически откатывается на CPU;
- режим **Офлайн** никогда не требует AI-сервер;
- режим **Авто** предпочитает локальную модель и использует сервер только если локальная модель отсутствует или не запускается.

Модель хранится в app-specific Downloads каталоге и не включается внутрь APK, поэтому APK остаётся небольшим.
